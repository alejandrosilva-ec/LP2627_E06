# Local System for Lost and Found Objects Management — Porto

**Course:** Laboratório de Programação (2026/2027) | **Component 1:** Data & Persistence

Lost and found application for the district of Porto, developed in Java with Hibernate and MySQL. This first component focuses on the domain model mapping (ORM), database persistence, entity relationships, and JPA queries.

## Database Configuration

1. Open MySQL Workbench and create the database by executing:
   ```sql
   CREATE DATABASE objetos_perdidos_db;
   ```
2. Edit the `src/main/resources/hibernate.cfg.xml` file. Adjust the `hibernate.connection.password` and `hibernate.connection.username` properties to match your local MySQL environment.
3. *Note: Do not commit real production credentials to the repository.*

With the property `hibernate.hbm2ddl.auto=update` configured, the relational tables, primary keys, and foreign keys are automatically generated by Hibernate upon the first startup.

## Build and Run Instructions

To compile the project and download all Maven dependencies, run:
```bash
mvn compile
```

To execute the automated persistence tests and business rules demonstration, run the `org.example.Main` class directly from your IDE, or via terminal using:
```bash
mvn exec:java -Dexec.mainClass="org.example.Main"
```

## Automated Demonstration (`Main.java`)

When executed, the program runs an automated, non-interactive demonstration designed to validate the project's persistence requirements:

1. **Hibernate Startup:** Initializes the configuration and opens the DB session.
2. **Data Seeding (US02 & US04):** Automatically persists initial entities if they don't already exist:
   - A "Supreme Admin" (`admin@upt.pt`, Profile: `ADMIN`).
   - A regular user (`esteban@upt.pt`, Profile: `USER`).
   - A found item published by the regular user, demonstrating the `@ManyToOne` relationship.
3. **Public Search Query (US01):** Executes a JPA query to list published items filtered by the Porto municipality, retrieving the title, category, and the publisher's name.
4. **Business Rules Validation (US08):**
   - A `USER` attempts to create a new `ADMIN` account and is successfully **blocked** by the system.
   - The `ADMIN` account attempts to create a new `ADMIN` account and is **allowed**, persisting the new record.

At the end of the execution, the session is safely closed. *Note: The demonstration accounts use simple, hardcoded passwords for development purposes.*

## Domain Model & Schema

| Entity | Table | Description |
|---|---|---|
| `ObjetoAchado` | `objetos_achados` | Found item details (title, description, category, color, municipality, location, date, contact, image url, status). |
| `Utilizador` | `utilizadores` | Registered user credentials. Implements `unique=true` constraints for Email and ID Document. |
| `RegistoContacto` | `registos_contacto` | Audit log for contact lookups to enforce the weekly limit anti-fraud mechanism (date/time, querying user, queried item). |

**Relationships** (Configured via `@ManyToOne` / Foreign Keys):
- `ObjetoAchado → Utilizador` (A user publishes many items)
- `RegistoContacto → Utilizador` (A user queries many contacts)
- `RegistoContacto → ObjetoAchado` (An item is queried by many users)

**Enumerations** (Persisted as `EnumType.STRING`):
`CategoriaObjeto` · `ConcelhoPorto` (18 municipalities) · `EstadoObjeto` (`ABERTO`, `RESOLVIDO`, `ARQUIVADO`) · `Perfil` (`USER`, `ADMIN`)
